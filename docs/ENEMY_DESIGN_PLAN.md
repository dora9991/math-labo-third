# 敵モンスターデザイン全量展開計画

## 目的と完了条件

空中学園 ASTRA ACADEMY の敵を、黒曜石・深藍・金・淡シアンを基調にした、子ども向けの節度を保つダークファンタジー調へ更新する。数学は文字ではなく形・構造・天文意匠として扱う。全画像は透明 512×512 WebP と 96×96 WebP を持ち、**ボス152体はIDごとに別デザイン**とする。

## 必要枚数

調査済みの `MONSTERS` は240体（`sample1`を含む）。生成の基準は「モンスターIDごとに1フルサイズ＋1サムネイル」。サムネイルはフルサイズから派生するため、生成・レビュー単位は240体、納品ファイルは480枚である。

| --- | ---: | --- | --- |

| unitSmallBoss | 32 | 単元モチーフを強化した中型の守護者 | 必須 |

## コンセプト付与ルール

1. まず章テーマを「数学の概念」から「物の構造」に翻訳する。
2. 次に役割を骨格で分離する（直立像、鳥、四足、甲虫、多脚、蛇、浮遊結晶など）。色だけを差にしない。
3. 同じ単元のボス列は段位を、体格・後光・装甲層・衛星モチーフで上げる。単なる巨大化は避ける。
4. 1章あたり、正面96pxで判別できる主モチーフを1つに絞る。文字・読める数式・ロゴは使わない。

## 作業量とフェーズ

| フェーズ | 内容 | 生成・確認単位 | 想定工数 |
| --- | --- | ---: | ---: |
| 0 | パイロットをゲームUIで確認、画風を凍結 | 10体 | 0.5–1日 |
| 1 | 全章のモチーフ台帳、ID別プロンプト、重複検査表 | 240 ID | 2–3日 |
| 2 | 雑魚87体を生成・透過・96px判読性レビュー | 87体 | 4–6日 |
| 3 | ボス152体を個別生成・隣接ボス比較レビュー | 152体 | 10–15日 |
| 4 | サムネイル派生、透明/余白/文字混入の一括検査 | 240体 | 1–2日 |
| 5 | 実装統合、ゲーム内背景・HPバーとの視認性QA | 全体 | 2–3日 |

合計は、生成再試行を各体20–30%見込んで約20–30人日。品質を保つには、ボスは一括生成よりも「同じ章の6–8体を横並びで比較→一体ずつ再生成」のレビューが重要である。

## 納品レイアウトと検査

```text
docs/enemy-pilot/                 # パイロット（この提出物）
src/assets/monsters/by-id/        # 実装フェーズで新設する本番候補
  boss_c1.webp
  boss_c1_small.webp
  ...
```

- フル: 512×512 RGBA WebP、被写体と後光を含めて四辺約6%の余白、床影なし。
- 小: フルから96×96 RGBA WebPへ派生（別途描き直しが必要な場合だけ例外）。
- 自動検査: サイズ、alpha最小値=0、alpha境界、ファイル名と `monster.id` の突合、OCR相当の文字混入確認。
- 目視検査: 96px/512px/実際のバトル背景、隣接ボスとのシルエット、フリンジ、怖さの上限、既存IP想起の有無。

## コード側で必要になる変更（今回は未実施）

`src/third/data/monsterImages.js` の現行 `MON_IMG_FULL` / `MON_IMG_SMALL`（art型を解決し `hue-rotate` を掛ける）を壊さず、ID専用画像を最優先にする。

1. `src/assets/monsters/by-id/<monsterId>.webp` と `<monsterId>_small.webp` を、ビルド時に解決できる形で列挙または `import.meta.glob` する。
2. `MON_IMG_BY_ID_FULL` と `MON_IMG_BY_ID_SMALL` を追加する。キーは `monster.id` のみ、値はアセットURL。
3. 画像取得関数を `byId[monster.id] ?? byArt[monster.imgArt ?? monster.art]` の順にする。smallも同じ順序で解決する。
4. ID専用画像が返った時は `imgHue` / `filter: hue-rotate()` を適用しない。フォールバックした既存art型だけに従来の色相回転を残す。
5. 存在しないID、読み込み失敗、small未提供は従来art型へ安全にフォールバックし、コンソールに開発時だけ警告を出す。
6. ユニットテストでは「専用画像優先」「専用small優先」「未登録IDは既存art+hue」「finalBoss/chapterBossの既存分岐維持」を固定する。

この方式なら、量産はID単位で追加でき、未着手の敵は現在の13アート型＋色相回転のまま動作する。既存データの `art`、`imgArt`、`imgHue` の意味も変えない。
