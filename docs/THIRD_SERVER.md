# 数学ラボ3 — サーバー版（チート対策）の手順と、守れる範囲

## 何を守るか
| 守るもの | 仕組み |
|---|---|
| **ガチャの抽選・チケット・所持キャラ・限界突破** | 状態は `third_player_state` に**サーバー(Edge Function `third-api`)だけ**が書く。ブラウザの保存を書き換えても変わらない。抽選もサーバーが暗号品質の乱数で行う |
| **経験値・コイン・バトルのご褒美** | バトルで解いた問題の記録(seed＋答え)をサーバーへ送り、**サーバーが seed から問題を作り直して採点**。「正解した/勝った」という自己申告は使わない |
| 二重取り・使い回し | 申請ごとの一意ID、解答(seed)の使用済み管理、申請間隔、同時送信の排他(楽観ロック) |
| 周回稼ぎ | チケットは各小単元の**初回クリアのみ**。2回目以降は経験値30%・コイン少、1日10回まで |
| 速すぎる解答 | 1.2秒未満の解答は正解に数えない／解答時間の合計が経過時間を超える申請は拒否 |

## 守れない/弱いところ（正直な限界）
- **答えそのものはブラウザのプログラム内にある**。本気で解析する人は、問題を作る関数を自分で動かして正しい答えを送れる。ただし得られるのは「小単元ごとの初回チケット1枚＋周回上限つきの少量報酬」まで（無限には増えない）。
- **メダル（はいち・れんしゅう）と、バトルの解放はまだブラウザ側**。書き換えるとバトルの入口は開くが、報酬は「サーバーが採点した正解数」が必要なので、学習せずにチケットは得られない。メダルのサーバー化は次の課題。
- 端末の時計は、サーバー時刻との差を補正して送る。

## 動作モード
- **サーバーモード**：`.env.local`（と本番ビルド環境）に `VITE_THIRD_SERVER=1`。ログイン中の生徒だけが使える。**これがチート対策版**。
- **ローカルモード（既定・開発用）**：同じ処理をブラウザ内で動かす。保存は localStorage＝書き換え可能。画面に「開発用のローカルモード」と出る。コンソールから `__thirdDev.giveTickets(20)` でチケット付与して試せる。

## デプロイ手順（1回だけ・kazuの操作）
1. `docs/supabase_third_setup.sql` を実行済みであること（済）。
2. 1ファイルにまとめる：
   ```bash
   npm run build:third-api      # → supabase/functions/third-api/bundle/index.ts（約1.3MB）
   ```
3. Supabase ダッシュボード → **Edge Functions → Deploy a new function**（名前は `third-api`）→ `bundle/index.ts` の中身を貼り付けて Deploy。
   - 「Verify JWT」は**ON のまま**（ログインしている生徒だけが呼べる）。
   - 貼り付けが重い/失敗する場合は Supabase CLI で `supabase functions deploy third-api`（要 `supabase login`）。
4. `.env.local` に `VITE_THIRD_SERVER=1` を足し、本番のビルド環境にも同じ値を設定して再ビルド。
5. **問題データや生成ロジックを変えたら**、`npm run build:third-api` でサーバーを作り直して再デプロイし、クライアントも再ビルド（版のずれたクライアントは「アプリが古いよ」と案内して拒否される）。
