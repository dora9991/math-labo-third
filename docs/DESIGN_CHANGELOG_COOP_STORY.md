# マルチ専用ストーリー「ともしびの回廊」（協力バトル）変更記録

2026-10-09 ／ ブランチ `claude/multi-raid-battle`（`claude/design-v2-hard-mode-fx` から。PR #2 の上に積んでいる）

kazuの指定：マルチは「同時に答える」形で、「マルチの敵」というより**マルチ専用のストーリー**。メダルのしくみもつける。経験値は低め。
21体の敵（各章の裏ボス）も使って、雑魚からスタートして、いい感じにストーリーを入れる。敵はある程度強く、答える時間は短め。

## 遊び方
1. 部屋をつくる／コードで入る → ホストが「はじめる」で共通パーティ5体が決まる（これまでどおり）。
2. 開始後は「🕯️ ともしびの回廊」のステージ一覧（全21）。ホストがステージをえらんで挑戦。**全員が前のステージをクリアしていると**次が開く（置いていかない）。
3. ステージ＝**雑魚2波 → その章の裏ボス**。はじまる前に場面（ミオ・シロフクロウバード・館長）。全員が読み終えるか、スキップすると始まる（最長90秒待つ）。
4. **全員が同時に答える**。ラウンドごとに自分の問題（その章の単元から1人ずつ別の問題）。制限時間は難しさで 13/17/23/29秒（短め）。次の問題の難しさはいつでも選べる。
   全員が答え終わる（離席中の人は待たない）か、時間切れでラウンド終了。
5. 正解した人の仲間（共通パーティのうち、その人が出した子）が攻撃。不正解・時間切れの人の分は攻撃なし。そのあと敵が必ず1回反撃して、**共通のパーティHP**が減る。
   雑魚を倒すとHPが12%回復。ボスのHPが半分以下になると攻撃が1.15倍。ボスは「ため→大技」などの技のパターン（一人用と同じ）。
6. 勝つと終わりの場面 → ごほうび。負けたら同じステージにもういちど。

## ごほうび
| もの | 内容 |
|---|---|
| メダル | ステージごとに 🥉クリア／🥈パーティHPが35%以上残ってクリア／🥇65%以上。いちばん良い色を記録。色が上がるたびにクリスタル+1 |
| 経験値（低め） | **本人のいまのパーティ5体に1体ずつ**。初回＝その章の最後の小単元の初回経験値の**35%**を5体で分ける（例：1章 27／7章 209）。2回目以降は10%で、1日3回まで |
| 称号・クリスタル | これまでの `applyRaidWin`（初回💎10・称号・学年ボーナス20・全制覇50）。周回はクリスタル1（1日3回まで） |
| ただ乗り防止 | その人の正解が5問未満だと、ごほうびなし（離席・何もしなかった人） |

※クリスタルの量（初回10）は kazu が 2026-09-25 に仮置きした値のまま。全21ステージ×(10+メダル最大2)＋ボーナスで、ガチャ（5個=1回）としてはかなり多いので、見直す余地あり（`raid.js` の `RAID`、`COOP.tierCrystals`）。

## 強さ（`src/third/raidBattle.js` の `RB`）
- 敵HP：その章の章ボス（一人用）を土台に、ボス ×0.41（ステージが進むほど増える：最後で ×2.2）。雑魚は ボスの 16%／26%（`RB.mobHp`）。
- 敵の攻撃：**共通パーティの最大HPに対する割合**（ボス平均 8.5%／ラウンド、雑魚 3%・4.5%）。どんな編成でも「何ラウンドで全滅するか」がそろう。強い編成は先に倒せる。
- シミュレーション（`node scripts/sim-raid-battle.mjs`・3人・各40回・各ステージの標準的なパーティを想定）：
  いろいろな子が混ざった教室で勝率 約6〜10割、普通の子ばかりだと約1〜9割（パーティの育ち具合しだい）、得意な子ばかりだと約9〜10割。1ステージ約6〜8分。
  金メダルは得意な子が多いときだけ出る程度。
- 調整は `RB`（`bossHp`・`hpGrowth`・`bossDmgFrac`・`mobDmgFrac`・`levelSec`・`waveHeal`・`tierGold/Silver`）と `COOP`（`raid.js`）の数字だけ。

## しくみ（サーバー）
- 戦闘の状態は部屋のJSON（`third_rooms.room.battle`）に持つ＝**SQLの変更なし**。サーバーだけが変える。採点もseedから作り直してサーバーが行う。
- サーバーに常駐のタイマーは無い。誰かが操作（答える／1.5秒おきの様子見 `room_battle_sync`）したときに、期限を過ぎていれば結果を出す。
- ほぼ同時の操作で保存が競合するので、サーバー側で読み直してやり直す（最大6回）。
- ごほうびは、勝った本人が自分で受け取る（`room_battle_claim`）。先に部屋へ「受け取り済み」の印を原子的に付けてから自分の状態を更新＝二重に受け取れない。ホストが部屋を閉じたあとでも受け取れる。
- 新しい操作：`room_battle_state / start / ready / sync / answer / claim`（`supabase/functions/third-api/handler.js`）。
- 部屋のパーティに、中1・中2・中3それぞれの経験値（`exps`）を保存（その章の学年のレベルで戦うため）。`exp` は従来どおり最大値。
- 保存データに `coop: { medals, daily }` を追加（`normalizeThirdState` が古いデータにも付ける）。

## 公開するときの順番（重要）
1. **先にサーバーの関数を登録**：`npm run build:third-api` → `npx supabase functions deploy third-api --project-ref mtzhbiadzqjhvhzzdsbn --use-api`（`dist-fn/deploy` で）。または `npm run release -- --skip-site`。新しい操作が増えるだけで、古い画面はそのまま動く。
2. **そのあとサイトを公開**：`npm run release -- --skip-fn`（または `npm run deploy`）。先にサイトを出すと、「みんなで戦う」の開始後が「うまくいかなかったよ」になる。
3. SQL の追加は不要（`docs/supabase_third_rooms_2026-09-25.sql` は実行済み）。

## まだ入っていないこと（次の候補）
- スキル（必殺）・状態異常・バフ：協力バトルでは使わない（回復役のキャラは、HPの足し・攻撃のみ）。
- 協力バトルの解答は、学習ログ（答えの記録・おすすめ）にまだ入らない。毎日の目標（💎）にも数えない。
- 「ハードモード」は協力バトルにはない。
- 部屋の人数が途中で減ったとき、その人の出した仲間は動かない（HPの数に入ったまま）。
- Realtime の在室表示は、第三者にも見える（チャンネルが公開）。サーバーは在室を信用していないので、害はない。
